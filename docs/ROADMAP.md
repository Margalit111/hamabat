# מה נשאר לעשות

## מצב נוכחי
האתר בנוי, נבדק (Lighthouse: נגישות, פרקטיקות ו־SEO = 100; ביצועים 84–99 בנייד) ומפורסם ב־Cloudflare.
כל דחיפה ל־`main` מפרסמת אוטומטית, ובנייה לילית מסתירה תוכן שפג תוקפו.

### בוצע
* מימוש ההדמיה ב־Next.js, עמודים וכתובות אמיתיות, SEO מלא, הצהרת נגישות ומדיניות פרטיות
* ביצועים: תמונות WebP, גופנים מאוחסנים עצמית, לוגו בקובץ נפרד, מטמון וכותרות אבטחה, אנימציית הלוגו מוקלת ורצה פעם אחת לביקור, CSS מנוקה
* תאריכים אמיתיים (`YYYY-MM-DD`): הצגה בעברית, סידור קורסים לפי `startDate`, הסתרה אוטומטית (`hideAfter`), `CourseInstance` ל־SEO
* פריסה אוטומטית ובנייה לילית
* בדיקת תקינות תוכן אוטומטית לפני כל בנייה (עוצרת טעויות עם הסבר בעברית)
* תמונת שיתוף כללית לדף הבית
* בדיקת נגישות פנימית (axe, ניגודיות, מקלדת, הגדלה ו־reflow) ותיקון הליקויים שנמצאו

## לפני שמראים ללקוח
* להשלים תוכן אמיתי ב־`site.json`: מועד פתיחה (`startDate`), מקום, משך ומחיר לכל קורס; מפגש הייעוץ הקרוב (כרגע נתוני הדגמה עם הערה "להמחשה בלבד"); לאשר עם הלקוח טלפון, וואטסאפ, מייל, צוות וניסוחים
* לבדוק בנייד אמיתי (אייפון ואנדרואיד) את כל העמודים
* להריץ ידנית את "Nightly rebuild" פעם אחת כדי לוודא שהיא עובדת

## לפני פרסום לציבור
* **דומיין:** לחבר ב־Cloudflare (Domains), להגדיר `NEXT_PUBLIC_SITE_URL` לכתובת הסופית ולבצע Retry build
* Google Search Console ושליחת `sitemap.xml`
* עורך דין שיעבור על הצהרת הנגישות ומדיניות הפרטיות; מומלץ גם בדיקת נגישות על ידי מומחה מוסמך
* אם מוסיפים אנליטיקה או עוגיות: לעדכן את מדיניות הפרטיות

## החלטה מול הלקוח: בעלות
כרגע הריפו (`Margalit111/hamabat`) וחשבון Cloudflare רשומים על חשבונות אישיים.
להחליט אם הלקוח פותח חשבונות משלו והבעלות מועברת אליו, או שהאתר מנוהל עבורו. העברה = ריפו חדש/העברת בעלות + חיבור מחדש ב־Cloudflare.

## מערכת ניהול (עוד לא נבנתה)
כרגע התוכן נערך כקובץ JSON ב־GitHub. זה עובד, אבל לא נוח למי שלא מתכנת. אפשרויות:
1. להישאר כך ולעדכן בעת הצורך.
2. CMS מוכן (Sanity / Payload / Directus): ממשק עריכה מקצועי, העלאת תמונות, היסטוריה, בלי לבנות הכול.
3. מערכת מותאמת: `api` (Node + PostgreSQL) + `admin` (React).

העיקרון בכל האפשרויות: האתר הציבורי נשאר קבצים סטטיים, בלי קוד ניהול ובלי גישה למסד נתונים.
מערכת הניהול מעדכנת את האתר רק דרך "פרסום" (יצירת `site.json` והפעלת בנייה):

```
admin (React) → api (Node + PostgreSQL) → "פרסום": site.json + בנייה → website (סטטי)
```

החיבור לאתר נעשה בנקודה אחת, `website/src/lib/content.ts` (`loadContent`): מחליפים קריאת קובץ בקריאה למערכת, ושאר האתר לא משתנה.
סכמת הנתונים כבר מוגדרת ב־`website/src/lib/types.ts` ובכל התאריכים בפורמט ISO.

### אבטחה (אם נבנה ממשק ניהול)
* תת־דומיין נפרד, `noindex`, ללא קישור מהאתר; Cloudflare Access או הגבלת IP לפני מסך ההתחברות
* התחברות עם 2FA, הרשאות לפי תפקיד (נבדקות בשרת), Rate limiting
* CORS מצומצם לדומיין הניהול בלבד; מסד הנתונים לא חשוף לאינטרנט
* גיבויים אוטומטיים ויומן פעולות (מי שינה מה ומתי)

## שיפורים אופציונליים
* פוטר בנייד עדיין גבוה (כ־143px) בגלל מספר הקישורים
* ציוני Lighthouse לביצועים ב־LCP נמדדים בסימולציה איטית; בדפדפן אמיתי הערכים טובים בהרבה. אם יידרש: דחיסת תמונות נוספת או CDN
* JS של React/Next הוא כ־470KB גולמי לעמוד (המחיר של הכלים), ואין הרבה מה לצמצם
